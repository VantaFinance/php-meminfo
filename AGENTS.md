## Project Overview

PHP Meminfo is a PHP extension that dumps the content of PHP memory as JSON, plus a browser UI
that analyzes those dumps entirely client-side to help track down memory leaks. (The former PHP CLI
analyzer has been removed; the UI replaces it.)

## Tech Stack

- **Programming language:** C (extension, Zend Engine API), TypeScript (browser UI); PHP only for
  tests, examples, fixture generators and repro scripts
- **Framework:** none for the extension; the UI is Svelte 5 on Vite (no SvelteKit, no backend)
- **Database:** none — the persistence format is a JSON dump file
- **ORM:** not applicable
- **Build:** `phpize` + `config.m4` for the extension, npm for the UI; optional Docker
  build (`Dockerfile`, `php:<version>-cli-alpine`) selected by `PHP_VERSION`; `CMakeLists.txt` is
  IDE-only (CLion code insight), never used to build the extension
- **Testing:** `.phpt` (extension), Vitest + Playwright (UI)
- **Supported PHP:** 7.0 – 8.5 (CI matrix)

## Project Structure

```
extension/                    C extension for the Zend Engine
  meminfo.c                   all extension implementation
  php_meminfo.h               public prototypes, module globals, version/copyright macros
  config.m4                   phpize/autotools build definition
  dump-meminfo                CLI wrapper over meminfo_dump_process() (installed by make install-cli)
  tests/                      .phpt tests
    fixtures/                 shared PHP fixtures for tests
ui/                           browser UI (TypeScript + Svelte 5 + Vite); dumps are parsed in a Web Worker
  src/lib/engine/             pure TS, no DOM: streaming parser, columnar store, analyses (Vitest)
    analyses/                 summary, top children, query, reference paths, dominators, suspects, diff, subgraph
  src/lib/worker/             worker protocol, DumpSession, dump.worker.ts, page-side DumpClient
  src/lib/components/         Svelte components; views/ holds one component per screen
    graph/                    Graph view drawing: Cytoscape elements/style/layout + GraphCanvas (lazy chunk)
  src/lib/state/              app state on Svelte 5 runes ($state.raw for everything from the worker)
  scripts/gen-dump.ts         synthetic dump generator with the extension's exact byte layout
  tests/fixtures/             real dumps: parity/ (frozen baselines of the former PHP analyzer, never
                              regenerated) and ui-only/ (regenerated by make-fixtures.php)
  tests-e2e/                  Playwright: app flow, privacy, memory budget, crash recovery
doc/                          usage guides and example scripts
.github/workflows/            CI: build the extension + run the .phpt suite on PHP 7.0–8.5 (Linux), plus PHP 8.1 on macOS and on Linux without sigqueue(), and a Swoole job (PHP 8.1/8.3/8.5); ui.yaml tests the UI and deploys it to GitHub Pages from master
Dockerfile                    builds + enables the extension for a given PHP_VERSION (image meminfo:php-X.Y)
.dockerignore                 keeps host build artifacts and ui/ out of the Docker build context
tools/repro/protobuf/         repro image (meminfo + ext-protobuf, optional ext-grpc) and repro.php dump check
tools/repro/swoole/           repro image (meminfo + ext-swoole) and coroutine scenarios: dumps inside coroutines, suspended coroutines, dump-meminfo on an event loop
tools/repro/memory/           probes for what a dump costs the dumped process: memory, speed, deep structures, signal path, target-side file hardening
CMakeLists.txt                IDE-only CLion project model over extension/ (Zend headers from .ide/)
CMakePresets.json             one CMake profile per PHP version (php-7.0 … php-8.5)
.ide/                         PHP headers extracted by `make ide` (git-ignored)
.ai-factory/                  AI Factory configuration and generated context
.claude/skills/               project-specific agent skills
```

Dependency direction in the UI: `components/` → `state/` → `worker/` client → (messages) →
`worker/session.ts` → `engine/`. The page side imports only types from `engine/`; `engine/` is pure
TypeScript with no DOM and is the layer covered by Vitest.

## Key Entry Points

| File | Purpose |
|---|---|
| `extension/meminfo.c` | Implements `meminfo_dump()` and `meminfo_dump_process()`, the memory traversal, the buffered writer, and the signal/interrupt path that dumps on request |
| `extension/php_meminfo.h` | Exported prototypes, the writer type, module globals, `MEMINFO_VERSION`, copyright macros |
| `extension/config.m4` | Build definition — new `.c` files must be registered here |
| `extension/dump-meminfo` | `dump-meminfo <pid>` command; prints the path of the dump the target wrote |
| `ui/src/lib/engine/parser.ts` | The UI's only reader of dump files: streaming tokenizer into the columnar `DumpStore` |
| `ui/src/lib/worker/session.ts` | Everything one dump worker answers; `dump.worker.ts` wires it to messages |
| `ui/src/App.svelte` | UI shell: load flow, navigation, views, inspector |
| `.github/workflows/build.yaml` | "Build and test the extension": CI matrix and `.phpt` invocations |
| `.github/workflows/ui.yaml` | UI checks, unit and e2e tests; on master, publishes the tested `ui/dist` to GitHub Pages |

## Common Commands

The root `Makefile` wraps the whole project and works with GNU Make 3.81 (macOS `/usr/bin/make`)
and later. Run `make help` for the full list. `check` and `ci` cover the extension only; the UI has
its own `ui-*` targets (Node 24+).

```bash
make build          # build the extension (phpize + configure + make, as needed)
make install-cli    # install the dump-meminfo command into $(PREFIX)/bin (default /usr/local)
make test           # the extension's .phpt suite (alias of test-ext)
make test-one TEST=tests/dump-array.phpt   # a single .phpt test
make lint           # php -l over doc/, extension/tests/fixtures, ui/tests/fixtures, tools/repro
make check          # lint + the .phpt suite
make ci             # what CI runs for the extension: build + the .phpt suite
make dump-example   # run doc/example.php, writing /tmp/php_mem_dump.json
make clean-ext      # remove extension build artifacts, incl. what phpize leaves (configure~, include/)
make clean          # clean-ext + clean-ui
make docker-build PHP_VERSION=7.4   # build image meminfo:php-7.4 with the extension enabled
make docker-test  PHP_VERSION=7.4   # the .phpt suite inside that image
make docker-matrix  # docker-test for every version in PHP_VERSIONS (7.0 – 8.5)
make docker-shell PHP_VERSION=7.4   # bash shell in the image
make docker-clean   # remove all meminfo:php-* images
make repro          # dump ext-protobuf objects (WITH_GRPC=1 adds ext-grpc) and check the JSON
make repro-test     # .phpt suite with ext-protobuf loaded (runs the protobuf-only test)
make repro-swoole PHP_VERSION=8.3        # coroutine scenarios under Swoole (PHP 8.1+), PASS/FAIL per check
make repro-swoole-test PHP_VERSION=8.3   # .phpt suite with ext-swoole loaded (runs the Swoole-only tests)
tools/repro/memory/compare.sh 8.1   # measure a dump's cost against a baseline revision (see its README)
make ide PHP_VERSION=7.4   # extract PHP 7.4 headers into .ide/php-7.4 for CLion
make ide-clean      # remove extracted headers
make ui-install     # npm ci in ui/
make ui-dev         # UI dev server
make ui-build       # static build in ui/dist (serve it; file:// does not work in Chromium/Safari)
make ui-check       # svelte-check + tsc
make ui-test        # engine tests (Vitest)
make ui-e2e         # end-to-end, privacy and memory tests (Playwright, Chromium)
make ui-fixtures    # regenerate ui/tests/fixtures/ui-only/ (PHP 8.1+ with meminfo); parity/ is frozen
```

Build against a specific PHP by overriding the toolchain variables:
`make build PHPIZE=/path/to/phpize PHP_CONFIG=/path/to/php-config PHP=/path/to/php`

The underlying commands, if you need them directly:

```bash
cd extension && phpize && ./configure --enable-meminfo && make
cd extension && REPORT_EXIT_STATUS=1 NO_INTERACTION=1 make test
```

## Agent Rules

- Decompose shell commands instead of chaining them with `&&`, so each step's outcome is visible:
  - Incorrect: `git checkout master && git pull`
  - Correct: first `git checkout master`, then `git pull origin master`
- The dump file format is a contract between `extension/` and `ui/`. A change on one side requires
  the matching change and tests (`.phpt` and Vitest) on the other in the same commit.
- The UI must never hold a dump on the main thread, read it whole (`Blob.text()`, `JSON.parse`) or
  send anything off the page; `ui-e2e` enforces the memory budget and the no-network rule.
- All changes must keep the PHP 7.0 – 8.5 CI matrix green. Engine API differences are handled with
  `PHP_VERSION_ID` preprocessor guards, not runtime checks.
